# Dataset

Full schema and stats live in [`../data/README.md`](../data/README.md); this doc covers provenance, splits, and how to work with the corpus.

## Provenance

The corpus is fully synthetic. Journal texts were generated by `openai/gpt-4o-mini` via OpenRouter from ground-truth graphs (a controlled vocabulary of 133 concepts, per-day scenarios drawn from a 16-template pool, per-participant writing styles). Each entry was then verified by the same model against its source graph, scoring: node coverage, edge expression, temporal correctness, hallucination count. Verification thresholds gate the `accept` / `review` / `reject` decisions.

Both languages use identical guardrails against connector words (English: `linked to`, `caused by`, …; German: `führte zu`, `verstärkte mein`, `linderte`, plus stem checks for `symptom`, `stressor`, `auslös`, `linder`), clinical labels, self-harm and violence content. Per-writing-style word ranges apply, with the German range clamped to the denser 80–160 band.

Generation config: temperature 0.8 (generation), 0.0 (verification), 4 retries with exponential backoff, 32 concurrent requests, budget 3 verify attempts + 3 generation attempts per sample. See `pipeline/config.example.json` for the exact settings; the run took ~10 hours and cost $45 at gpt-4o-mini rates.

## Splits

Participant-independent 50 / 30 / 20 split, stratified by language, seed 42. Every participant contributes 14 consecutive days; a participant belongs to exactly one split.

| split | participants | node examples | edge examples (hard neg, ratio 1.0) |
|---|---:|---:|---:|
| train | 1,705 | 20,679 | 261,110 |
| dev | 1,023 | 12,390 | 156,064 |
| test | 682 | 8,246 | 103,798 |

Language stratification: EN fraction 0.508 / 0.509 / 0.505 across train / dev / test (max spread 0.4 pp).

## Hard vs random negatives

- **Random** (v1 behaviour, `--negatives random`): per-graph uniform-random sampling of unconnected node pairs, ratio 1:1.
- **Hard** (default, `--negatives hard`): sample within-graph negatives so the negatives' TYPE-PAIR distribution matches the positives' type-pair distribution. Where a type pair has too few candidates, the deficit is filled from the nearest available pairs (sharing ≥1 type first, then any). This removes the type-pair shortcut that made v1 edge scores look higher than they should. Achieved TV distance ~0.26 (a floor for this graph shape); details in the per-split `negative_match.json`.

## Labels

`node_prediction/labels.json` records the 130-label index used for training. Three concepts in the pool (`activity_alcohol_use`, `coping_distraction`, `coping_family_support`) have zero support in any split and are excluded; adding them back would only add false positives. All 130 kept labels have train support ≥ 20.

## Working with the corpus

Inspect one participant-day: `python scripts/inspect_sample.py --participant p00001 --day 1`.

Sanity-check line counts and connectivity: `python scripts/validate_dataset.py`.

Rebuild edge splits from source: `python scripts/build_edge_split.py --data-dir modeling/data_v2`.

Reproduce a stats table: `python scripts/stats.py`.

## Ethics

- **Fully synthetic**: no human subjects, no scraped text, no PII.
- **Participant metadata** (age, gender, occupation, writing style, recurring stressors, coping style) is randomly assembled from small enumerated inventories in `pipeline/scenarios.py`.
- **Content**: common mental-health themes at the level a general audience would recognize. Guardrails prohibit self-harm, suicide, abuse, violence, and diagnostic labels (depression, PTSD, …).
- **Language coverage**: EN and DE. German entries were generated in a native register with idiomatic connector checks, not translated from English.
- **Intended use**: benchmark for structured extraction from short narrative text. **Out of scope**: clinical decision support, diagnostic use, triage, or any application that treats the outputs as evidence about a real person's mental state.
